Task 2 — Dependency Confusion Resolver Simulation

Comparison of pip package resolver behavior between Merged Mode (--extra-index-url) and Single-Index Mode (--index-url) for package acme-internal-utils.

Configuration A: Merged Indexes

--extra-index-url (VULNERABLE)
Private Index
acme-internal-utils
v1.4.0
Public PyPI (Attacker)
acme-internal-utils
v99.0.0 ★ PICKED
Verdict: Confused — installs v99.0.0 from PUBLIC

--extra-index-url merges private and public registries into a single candidate pool. The resolver enforces PEP 440 ordering ("highest version wins") with no source trust boundaries. Because 99.0.0 > 1.4.0, the attacker's public wheel is installed and its malicious setup.py runs at install time as root/developer.

Configuration B: Single Index

--index-url (SECURE DEFENSE)
Private Index
acme-internal-utils
v1.4.0 ★ PICKED
Public PyPI (Attacker)
acme-internal-utils
v99.0.0 (IGNORED)
Verdict: Safe — installs v1.4.0 from PRIVATE

--index-url explicitly designates exactly ONE authoritative index. The resolver never queries the public PyPI index for this package name, meaning the public 99.0.0 candidate is never fetched, evaluated, or installed. The attack vector is completely severed.
